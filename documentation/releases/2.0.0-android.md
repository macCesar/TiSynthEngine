# Android 2.0.0 — release preparation

Status: prepared, not published. Proposed tag: `android-2.0.0`. Proposed title: **Android 2.0.0**.

- [x] Add reusable Sound definitions, playback overrides and owned note, repetition and pattern controls.
- [x] Validate `set()` atomically while preserving active executions and invalidate old controls after shutdown.
- [x] Preserve legacy playback signatures, returns, identifiers, events and native audio behavior.
- [x] Unify runtime metadata on the installed module’s `version` and provide updated TypeScript declarations and examples.
- [x] Fix held-ID alias retention and cover native boundaries, revision resets and bounded memory lifetimes.

**Migration:** replace runtime `apiVersion` reads with `version`. Playback compatibility is retained; metadata now uses a single module version. See [Sound API](../sound-api.md) for the method mapping and [validation](../sound-api-validation.md) for acoustic results, measured performance and open limits. The virtual Android telemetry/watchdog failure remains unexplained; no universal zero-underrun or indefinite-memory guarantee is claimed.

Requires Titanium SDK 13.2.0.GA or later and Android compile API 35 or later. Asset: `ti.synthengine-android-2.0.0.zip`.

Before publishing, integrate the implementation into `main`, build both platforms from that exact clean commit, refresh packaged documentation, verify ZIP versions/integrity and record SHA256 digests. Create separate Android and iOS releases following the existing tag convention. Do not publish the current feature-branch preparation as a default-branch release.
